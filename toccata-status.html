Kaspa Toccata status

Toccata is live on Kaspa mainnet. It activated at DAA score 474,165,565 on June 30, 2026, adding covenant-style programmability to Kaspa's L1. Rusty Kaspa v2.0.1 is the current upgrade release; v2.0.0 set the activation parameters.

Summary: Toccata adds Kaspa L1 covenants, covenant IDs, ZK proof hooks, sequencing commitments, and based-app foundations. Next to check: upgraded-node behavior, wallets, explorers, SDKs, examples, real app use.

Read the limits too: Risks and Open Questions covers adoption and roadmap execution; Smart-Contract Status separates Toccata from mature live app infrastructure.

What changes

Toccata adds expressiveness

Toccata adds L1 rule surfaces: covenant scripting, covenant IDs, ZK proof verification, sequencing commitments, foundations for based apps. It does not turn Kaspa into an EVM, and full vProgs still need their own roadmap and activation evidence.

Covenants

Constrained UTXO spends for vaults, escrow paths, asset rules, and other bounded money rules.

Covenant IDs

Consensus-tracked covenant lineage gives state membership a protocol-level reference.

ZK proof checks

A script can verify selected proof systems. App truth still rests on the statement and inputs being proved, not the proof mechanism alone.

KIP-21 lanes

App-local activity commitments let a prover follow its own lane instead of the whole DAG.

Based apps

Standalone apps can anchor state to Kaspa ordering, proofs, settlement, or exits.

vProgs later

Full app-to-app composition stays future architecture. Toccata's mainnet activation covers a narrower slice.

Claim wording

Toccata is live. It activated at DAA score 474,165,565. Wallets, explorers, SDKs, examples, and app use are separate, still-developing claims.
What it can enable

Vault rules, asset rules, escrow paths, assurance contracts, proof checks, sequencing commitments, standalone based-app foundations.

Separate evidence needed

Mature native DeFi, full vProgs, full app-to-app atomic composition, and mainnet production readiness don't follow automatically from activation.

What to verify next

Node behavior, transaction submission, wallet support, explorer support, SDK support, mainnet transactions using the new rules.

Operator checklist

Who needs to check their path

The Toccata guide reads as an operator and integrator checklist. After activation, the work shifts from upgrade readiness to field checks: node behavior, transaction submission, wallet support, explorer support, app receipts.

Ordinary users

No node action needed unless they run infrastructure. Holding or sending KAS through a normal wallet is a different job than maintaining consensus or service infrastructure.

Node operators

Run Rusty Kaspa v2.0.1 or newer. The node database upgrade only goes one way: the only path back is a resync.

Wallets and submitters

Use fee estimation, or update fixed-fee code to 100 sompi * max(compute grams, 2 * transaction bytes). Upgraded nodes apply the higher standard-fee policy to direct RPC submissions.

Exchanges and indexers

Update SDKs or regenerate bindings, then handle transaction version 1, storageMass/storage_mass, computeBudget, output covenants, and UTXO covenant_id.

Miners and pools

Test block templates, job distribution, solved block reconstruction, and SubmitBlock against Testnet-10. A block that strips post-Toccata fields can turn invalid after the activation score.

Pool accounting

Check GetBlockRewardInfo, and GetSeqCommitLaneProof where lane-proof data matters. Infrastructure detail, but the kind that breaks payouts if skipped.
