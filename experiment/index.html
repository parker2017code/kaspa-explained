Apps

Every app here shares the same client-side, non-custodial pattern: your own wallet, ordinary TN10 transactions carrying a small app-specific payload, no backend, no shared database. Each links out to its own page.

Wallet, messaging, feed, rooms

Send TN10 payments, encrypted DMs, group chat rooms, a public feed, and display names. You're on it now.

Tip jar

Send a tip and a message to a shared address, see a live leaderboard of top tippers.

 Polls

Create a poll, vote, watch results tally live from the chain itself.

 Task board

Post, claim, and complete tasks. State is computed by replaying the chain, no database.

 Vault

Pay-to-unlock content locked behind a real hash-lock script, not a database flag. Claiming a payment means publishing the secret that unlocks it, on-chain.

 Discover

Real open-source networks for music, chat, storage, and video that Kaspa doesn't try to replace.

Send

This is a public play wallet. Sends are capped at 10 tKAS per transaction: testnet coins, no real value, but let's keep it sane.

Public feed

One shared TN10 address everyone posts to and reads from, unencrypted since a feed is meant to be public. Same "L1 transaction as a public post" pattern as the open-source thesheepcat/K microblogging app.

Group chat room

A room name derives a shared posting address and a shared password (SDK's own password-based cipher). Anyone who knows the room name can join, same trust model as an unlisted invite link. Try "kaspa-builders" from two different wallets.

Messaging (encrypted, on-chain)

Same design as the open-source Kasia messaging app: an encrypted payload riding inside an ordinary TN10 transaction, no server. Uses the official SDK's own CryptoBox (X25519 + XChaCha20Poly1305) instead of Kasia's forked cipher-wasm. A wallet must publish its messaging key once before others can message it.
