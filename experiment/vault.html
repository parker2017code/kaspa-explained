TN10 Vault

Pay to unlock, enforced by the script engine instead of a server's word. A creator locks a small TN10 payment behind a hash-lock spending condition. The only way to claim that payment is to publish the secret that unlocks it, on-chain, in public. Once that secret is published, anyone who was waiting for it can use it.

What this actually is

The locking script is OP_SHA256 <hash> OP_EQUALVERIFY <pubkey> OP_CHECKSIG, wrapped as pay-to-script-hash (P2SH) with the official SDK's ScriptBuilder, payToScriptHashScript, and createTransaction. This is the same hash-lock shape atomic swaps use, not a hand-rolled cipher. It is a different, older primitive than Kaspa's newer covenant-ID mechanism (CovenantBinding, covenantId(), the OpInputCovenantId/OpOutputCovenantId opcodes), which this page does not use. Both are real script-level primitives in the same SDK; this page names which one it built so the two don't get flattened into one vague "smart contracts" claim.

The mechanism generalizes past this demo: the same pay-to-reveal pattern is what would gate a music or video file (buyer pays, creator's claim reveals the decryption key), a pay-per-call AI model, or a paywalled article. Escrow and assurance-contract refunds are the same idea with a second, timeout-gated spending path (OP_CHECKLOCKTIMEVERIFY) added to the script, not a different system. This page demonstrates the core primitive end to end with real TN10 transactions; it does not claim to be a finished marketplace.

The actual covenant-ID mechanism this page skipped is real and already tested on a different network: a public TN12 covenant experiment map has accepted-transaction evidence for a budget cap that can't drain all at once, a controlled asset move that needs its controller's co-signature, and a step-by-step workflow with a recovery timeout, the vault, escrow, and shop-order shapes this experiment keeps coming back to. It's testnet evidence on a separate network, not this page's own work, and not a stand-in for mainnet product evidence.

Lock an item

Content is capped at 300 characters for this demo (it stands in for a link or a decryption key you'd hand out for real media, not the media itself). It is encrypted client-side with a random 32-byte secret before anything is published. Only this secret's SHA-256 hash goes into the locking script; the secret itself stays local to your browser until you claim a payment.
