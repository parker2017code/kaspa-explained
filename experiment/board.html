TN10 Task Board

A shared task board with no server and no database. Anyone can post a task, anyone can claim an open one, and whoever claimed it can mark it complete, all as plain TN10 transactions to one shared address. The board you see below is computed by replaying that address's full transaction history, not stored anywhere.

How this board works

There's no backend holding "the real state." Posting, claiming, and completing a task are each a plain TN10 transaction sent to the one shared address below, with a small text payload: task:1:new:<poster>:<title>, task:1:claim:<taskTxid>:<claimer>, or task:1:done:<taskTxid>:<completer>. This page (and anyone else's) computes the board by fetching that address's full transaction history, sorting it by time, and replaying those events in order. A task's own transaction id becomes the id everyone references afterward. Same "based app" pattern as richer Kaspa app state: deterministic replay over accepted transactions instead of a database.

The claim/complete rules this UI enforces (only claim what's currently open, only complete what you're currently shown as the claimer of) are this page's own courtesy policy, computed from the replay. They are not enforced by the protocol: nothing on-chain stops another wallet from broadcasting its own claim or done event for the same task. Anyone can technically claim or complete a task on-chain; this UI just guides normal use, the same wallet-policy trust model as the rest of this experiment, not script-enforced or trustless.
