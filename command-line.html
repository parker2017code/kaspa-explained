Mental model

Verification ladder

1. Explorer

An explorer shows whether a transaction appears accepted. It is one interface's read of the chain, not the chain itself.

2. Second source

Check a second explorer, API, wallet, or indexer. Two hosted views that disagree are a signal to slow down, not a coincidence to ignore.

3. Your wallet

Network, address, balance, transaction history, fee, and signing intent, read from wallet software you control.

4. Your node

Run or query a node to check chain state directly, with no hosted interface in between.

Climb the ladder when the situation calls for it. A normal payment doesn't need every rung.

Hosted API

KDP commands and boundaries

The Kaspa Developer Platform is a hosted API for chain data, transaction checks, block queries, and a node RPC proxy. It works for prototypes, dashboards, exchange and wallet integrations, and second-source checks.

POST

Transaction acceptance

Batch-check txids for acceptance, accepting block hash, and confirmation count.

curl --request POST \
  --url https://api.kas.fyi/v1/transactions/acceptance \
  --header 'Content-Type: application/json' \
  --header 'x-api-key: <api-key>' \
  --data '{"transactionIds":["<txid>"]}'
GET

DAA-score blocks

Read a bounded DAA-score range. KDP caps each request at 100 scores.

curl --request GET \
  --url https://api.kas.fyi/v1/blocks/daa-score/{daa_score_start}/{daa_score_end} \
  --header 'x-api-key: <api-key>'

For paginated jobs, advance the range one block at a time and record the last checked score.

GET

Blue-score blocks

Read blocks by blue score when that's the progress marker your app already tracks.

curl --request GET \
  --url https://api.kas.fyi/v1/blocks/blue-score/{blue_score_start}/{blue_score_end} \
  --header 'x-api-key: <api-key>'
GET

Address history

Large address histories need cursor pagination. Cache results and handle rate limits, or the requests pile up fast.

curl --request GET \
  --url 'https://api.kas.fyi/v1/addresses/<address>/transactions?limit=100' \
  --header 'x-api-key: <api-key>'
DATA

API data rules

Amounts arrive as sompi strings. Hashes are 64-character hex. Addresses carry the kaspa: prefix. Timestamps are Unix milliseconds.

1 KAS = 100000000 SOMPI
amount: "31112708372"
blockTime: 1749531022210
LIMITS

Rate limits and keys

Send the API key in x-api-key. A 401 means the key is wrong; a 429 means back off. Watch the rate-limit headers and request-unit cost to see it coming first.

ratelimit-limit: 500;w=1
ratelimit-remaining: 490
x-request-cost-ru: 10
BOUNDARY

Production boundary

API keys, rate limits, pricing, and provider uptime are dependencies on someone else's infrastructure. A production app that needs reliability, privacy, or scale should plan its own node, indexer, or a redundant provider path.

KDP is a hosted read path, not a source of truth. Protocol status comes from source, releases, KIPs, nodes, and network evidence.

Mainnet

Run a Rusty Kaspa node

Prerequisites: Docker for the container route, or Rust/Cargo for the source route. A node verifies chain state. It does not create or protect wallet keys on its own.

Docker route with persistent storage:

docker pull kaspanet/rusty-kaspad:latest
mkdir -p ~/kaspa-data
docker run -d --name kaspa-node --restart unless-stopped \
  -v ~/kaspa-data:/app/data \
  -p 16110:16110 -p 16111:16111 -p 17110:17110 -p 18110:18110 \
  kaspanet/rusty-kaspad:latest

Basic container checks:

docker ps
docker logs --tail=80 kaspa-node

Source-build route from the Rusty Kaspa README:

git clone https://github.com/kaspanet/rusty-kaspa
cd rusty-kaspa
cargo run --release --bin kaspad

Mainnet node with UTXO indexing:

cargo run --release --bin kaspad -- --utxoindex

Use --utxoindex when wallet or UTXO queries need indexed UTXO state. A node that hasn't finished syncing will answer confidently and wrongly, so wait for sync before trusting what it says.

Wallet and RPC

Open the terminal wallet/RPC path

From a Rusty Kaspa checkout:

cd cli
cargo run --release

This is the current entry point into the Rusty Kaspa terminal RPC and wallet runtime. Before creating wallets or signing anything:

Check network

Confirm mainnet or testnet before creating or importing wallet material. Wrong network, wrong keys.

Check files

Find where wallet files, keys, and local state actually live before you need them in a hurry.

Check intent

For every transaction, read the address, amount, fee, network, and whether it's a send, sweep, or self-transfer.

Test small

Send a tiny amount first, then confirm the accepted txid through an independent source before sending more.

wRPC

Enable a JSON WebSocket RPC endpoint

wRPC is optional and off by default in Rusty Kaspa. For JSON wRPC:

cargo run --release --bin kaspad -- --utxoindex --rpclisten-json=default

This opens a WebSocket that SDKs and scripts can query for node state. Bind it carefully on public machines. Opening an RPC endpoint does nothing for key isolation, signing discipline, or verification; those stay your job.

Use wRPC when an app needs to read accepted transactions, inspect payload-capable routes, or compare indexer state against what the node itself observes.

Testnet

Practice before mainnet

Generic Rusty Kaspa testnet route:

cargo run --release --bin kaspad -- --testnet

Older hard-fork testnet guides used explicit suffixes, for example:

kaspad --testnet --netsuffix=10 --utxoindex
cargo run --bin kaspad --release -- --testnet --netsuffix=10 --utxoindex

For TN12/Toccata work, check the current netsuffix, release, endpoint, and flags against active public docs before running anything. The older TN10 examples are Crescendo-era context, not current instructions. The Rusty Kaspa tn10-toc2 and tn10-toc3 pre-releases, plus the Testnet-10 REST status endpoint, are the current Testnet-10 Toccata activation and hardening evidence.

TN12 practice

Use the proof lab for covenant-shaped testnet work

TN12 is where covenant, payload, and replay experiments get tested before they touch mainnet behavior. In the TN12 repo, the basic route is:

git clone https://github.com/parker2017code/tn12-covenant-vault-demo
cd tn12-covenant-vault-demo
npm ci
npm run check:all
npm run check:tn12
npm run playground:wallets

Fund only the printed kaspatest: addresses with faucet tKAS, check txids in the TN12 explorer, and replay before trusting what the app reports as state. Anything run with --submit is a real TN12 broadcast, not a dry run.

Status: testnet practice. Mainnet wallet, custody, and Toccata activation claims need mainnet evidence, not testnet results.
