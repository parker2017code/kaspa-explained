# V5 Argent business contracts

These contracts represent scarce game inventory and native Testnet-10 coin. They make no claim about delivery of physical goods. They have local compiler and VM evidence; this directory alone is not evidence of node acceptance or deployment.

`business.ag` owns five integer balances: crops, wood, ore, tools, and bread. A trade spends two independent Business covenants. Each owner (or explicitly delegated operator) signs the complete transaction. Argent checks both prior and successor templates; mirrored state deltas preserve every resource. Each input checks its own native value delta, while the mirrored `last_coin` state field forces the peer to use the opposite delta. `last_coin` stores the delta plus 1,000,000,000,000 to retain a nonnegative fixed-width state representation. External native P2PK inputs pay the fee, preserving combined business value.

Each business checks an issuer data signature over SHA256(world || covenant ID || owner), with each component 32 bytes. The deployment's world value supplies the domain. The issuer must issue this certificate only after checking the accepted genesis against its recorded owner, template, starting inventory, and zero mandate. A certificate is not self-authorizing genesis evidence. A legitimate business rejects a peer with a different issuer/world or invalid certificate. The SDK's `signScriptHash` returns a push prefix and sighash suffix; remove both for the 64-byte data signature. Exact SDK-produced certificates are verified by the VM fixtures.

The owner can fund its business from native wallet coins. The fund entry raises only business value by the explicit positive amount and increments sequence, preserving all resources, identity, and mandate fields. Wallet P2PK inputs pay the amount plus fee and receive owned change. There is no withdrawal entry.

Owner configuration preserves identity and inventory, increments sequence, and sets the operator, remaining cumulative spending allowances, and `min_receive`. Allowances cannot be replenished by receiving inventory. `min_receive` means the aggregate number of positive resource units received per delegated trade. It is not a coin price or exchange rate. Zero allows a delegated sale or gift within its spending allowances. Empty configuration restores the owner as operator and zeros all allowances. Restock requires both owner and issuer transaction signatures.

`observer.ag` is independently compiled. It imports the BusinessState capsule and uses open `actor_type<BusinessState>` observation. The composed fixture spends a Business and Observer together, checks the exact configuration successor, and rejects a false template witness.

Rebuild with `node scripts/build-v5-argent.mjs`. Verify with `node scripts/v5-argent-fixtures.mjs --check-vm`. The suite compares exact SDK unlock bytes to generated SilverScript ABI bytes, executes all inputs in the covenant VM, and compares JavaScript mass calculations to native Testnet consensus calculations. It includes partial-signature recovery, hostile wire plans, and the maximum eight external fee inputs.

The browser adapter's structural verification and signature completeness checks do not replace cryptographic VM verification. The browser must bind a rebuilt plan to the action actually reviewed: business covenant/outpoint, prior state, exact deltas or operator policy, expected issuer/world, local signing slots, and local coin debit. Journal complete signed bytes before submitting and apply state only after node acceptance. Native SDK `verifyMessage` is not an input-signature or certificate verifier.
