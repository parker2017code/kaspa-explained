GHOSTDAG explained

Kaspa's losing blocks still count toward security. GHOSTDAG is the rule that keeps them in the graph and turns a tangle of parallel proof-of-work blocks into one ordered history.

The mechanism

Why Kaspa needs it

Problem

Fast block times mean honest miners regularly find blocks within moments of each other.

Old shape

A single chain has to pick one branch. The losing branch's work gets thrown away as orphaned or stale.

Kaspa shape

A blockDAG keeps both blocks. Neither gets discarded.

Ordering rule

It splits the graph into a blue set and a red set, then applies the same ranking procedure at every node.

What you see

Your transaction lands in a block fast. Confidence that the block stays blue builds as more blocks reference it.

The catch

Fast inclusion is not irreversibility. How final your payment is still depends on confirmation depth and how much risk the recipient will tolerate.

Common mix-ups

What GHOSTDAG is not

QuestionAnswerBest wording
Is GHOSTDAG live?LiveGHOSTDAG is Kaspa's live blockDAG ordering rule.
Is it DAGKnight?NoDAGKnight is a separate, later consensus design.
Does it remove finality risk?NoInclusion is fast. Confirmation confidence is still probabilistic.
Does it mean unlimited TPS?NoThroughput is bounded by block capacity, mempool policy, fees, and demand.
